# Public interface

`index.html`, `style.css`, `app.js`, `interview.js`, `readiness.js`, `readiness-language.js`, `mock.js`, `python-practice.js`, and `sql-practice.js` are the public frontend sources. The Pages build packages them with real language logos, 116 prepared lessons, and 40 original JavaScript challenges from `content/`. Practice has search, difficulty filters, saved problems, attempt history, and scheduled review. Interview preparation has eight pattern guides, four company prep paths with real marks, and timed two problem rounds with saved drafts, explanation notes, and a results report. The practice plan suggests five JavaScript problems plus Python and SQL next steps from missed, due, and new work. Twelve original system design and behavioral mocks have timers, saved drafts, and self-review rubrics. Company paths are independently curated themes; they are not claims about actual interview questions or endorsements. Solving a challenge for the first time earns local practice coins by difficulty. The first interview hint is free and the second costs five coins. The browser keeps progress locally and can export or import a backup. Activity streaks count days with completed work. Practice code runs in a sandboxed frame with a three second limit.

The live tutor uses saved lesson notes. The public frontend now has a configuration-gated Google/GitHub sign-in module and a Grok API hook. Neither activates without a Firebase project or a server deployed with an xAI API key. Python practice uses Pyodide in a browser worker with visible tests, saved drafts, and a timeout; it downloads the runtime on first use. SQL practice runs 12 original exercises against two SQLite datasets each in a worker, with saved drafts and a timeout. The SQLite runtime is bundled locally. See [account setup](../../docs/AUTH_SETUP.md) and [tutor setup](../../docs/TUTOR_SETUP.md). A private judge and community leaderboard still require server services that GitHub Pages does not provide. `apps/web` contains a separate Next.js implementation with the server based Grok route.

The public site links to the [official LeetCode problemset](https://leetcode.com/problemset/) for exact LeetCode questions. Devoal's own question bank is original. It does not copy LeetCode statements, tests, company tags, or their full catalog.

Coding results include measured execution milliseconds, test pass percentage, and recent run graphs. JavaScript times code setup and function execution in its sandbox; Python times code execution and function calls using `perf_counter`; SQL times query execution after dataset setup. Runtime startup and test comparison are excluded. Speed comparisons use the learner's previous successful runs of the same problem and benchmark version, excluding ties and failed runs. These are local measurements, affected by browser/device differences, not a population ranking or server judge score. Timed interview submissions retain these measurements in their reports.

The account panel uses the provider avatar with an initials fallback and supports display name, bio, learning preferences, and X/LinkedIn usernames. The header provides Dark, Light, and System appearance modes. Profile preferences participate in account sync and backups; appearance is saved per device.
